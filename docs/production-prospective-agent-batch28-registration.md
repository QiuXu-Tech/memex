The initial Express success control asserted before its asynchronous callback and failed on both versions; it was corrected and rerun before registration. A preliminary qs baseline `require` was also run in the dedicated VM outside the inner network-disabled sandbox; the recorded qualification runs used the sandbox. Dependencies were installed without lifecycle scripts, with locks recorded in the manifest. Checks are narrow and proposed references are not maintainer acceptance.

After four batch 27 attempts stopped when the model requested more than four tools in one response, this batch changes the runner: it executes at most the first four, records each remaining call as **not executed**, and returns that result to the model so it may continue within the same turn budget. The change applies equally to both arms and is tested, but makes cross-batch comparisons exploratory. Model names, AI blind-rating rubric, separate adjudicator and bounded 503-only retries follow [batch 27](production-prospective-agent-batch27-registration.md). The estimated budget is below $1, not a hard cap. Shared gateway provenance, solution exposure, partial checks and short issue histories prevent production or independence claims.
