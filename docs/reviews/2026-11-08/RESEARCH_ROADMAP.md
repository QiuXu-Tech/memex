# Memex 未来迭代与研究计划

基于 [2026-11-08 审查](AUDIT.md)，对应基线 `5bf65f6ede777c00cf35ec2ba1e4b14dbc17f182`。这是可执行的**建议路线**，不是维护者已经批准的发行版本、资源预算或效果承诺。版本名用于规划；是否采用由维护者决定。按验收门推进，不按日历强行发布。

## 1. 研发目标与不做的事情

目标不是“存下尽可能多 token”，而是：**在不损坏历史、不扩大读取范围、不把陈旧判断当事实的前提下，让真实 Agent 用更少的全任务成本完成至少同样可靠的工作。**

先保留现有 JavaScript 本地 Core、SQLite、Markdown、轻量适配器。每项改动必须对应 [findings.json](findings.json) 或下文有证伪条件的研究假设。默认不增加后端服务、分布式数据库、大型自训练模型或自动修改事实的机制。只有测量证明同步路径或检索策略是实际瓶颈，才引入对应的 worker 或模型组件。

明确分两条线：

- **产品主线：** 可安装、可恢复、可观测的 API/文本上下文层。无需 GPU、无需训练即可完成第一阶段价值验证。
- **研究支线：** 学习型页选择、窗口组合、可控的原生 KV/offload 适配。与产品主线解耦、默认关闭，不用原型实验的成功为主线作生产担保。

原始历史实验不覆盖、不重写；错误用勘误和新的运行记录纠正。真实用户资料未经明确授权，不用作公开测试、模型训练或远程评审数据。

## 3. R0：冻结最小契约，而非重新发明架构

将以下语义作为简短、可测试的合同保存。不要为了表达合同先搭建大型框架。

**写入合同。** 区分 create、带版本的 patch、status transition。稳定 ID 归属不可由 UPSERT 隐式转移；异步 enrichment 不能覆盖后来的 lifecycle、scope 或正文。来源可信度和调用者信心分开；“Agent 写入”不等于事实已验证。

**读取合同。** 可见域在入口和实际读写处一致；record ID、page ID、event/block ID 各有定义。正文行号与字符续读坐标固定。请求被裁剪、资料不存在、资料不可见、超预算、源读取失败必须返回不同的状态；对不可见对象的响应仍不能泄露其存在。

**预算合同。** hard 模式不得超额，即使 pinned；soft 模式可以返回 exceeded，但宿主须明确接受。token 预算包括前缀、标题、引用、数据包络和回执。字符数估算只可标为估算，不能当真实 tokenizer 断言。

**恢复合同。** 文件、SQLite canonical events、完成标记和迁移版本共同构成状态。可恢复不等于断电零丢失；备份字节完整不等于可启动。所有危险恢复动作在 staging 中验证，旧状态有回滚路径。

**执行权限合同。** 工具 discovery 与实际执行授权不是同一件事。当前 `--all-tools` 是披露过的兼容性开关；如新增严格只读/维护权限，应采用显式 allow-list 参数并说明破坏性变更，不能悄悄改变旧参数含义。

每个合同至少对应一项边界测试；先保留失败输出，再在修复 PR 中转换为通过断言。不要把“复现脚本退出 0”误写成“产品没有缺陷”。

## 4. R1：先把可恢复的数据底座修牢

### 4.1 建议实现 PR 顺序

| PR | 单一目的与主要范围 | 必须新增的检查 | 回滚/兼容要求 |
|---|---|---|---|
| PR-01 | F01：Core/适配器本地 bootstrap 与真实安装 smoke | 空 HOME、干净检出、没有 test loader 的 MCP/Claude/Codex 启动 | 不覆写已有客户配置；不提交 node_modules |
| PR-02 | F14/F15：备份格式校验、staging restore、旧目标保留 | 缺 DB/空清单/复制失败/磁盘满/交换中断/可恢复性 | 保留旧备份读取；遇未知格式 fail closed；禁止就地半恢复 |
| PR-03 | F07：enableLevel 原子合并 | 两连接确定性交错、多进程压力、重复调用 | 保留已开启位；不新增隐含关闭机制 |
| PR-04 | F08/F09：事件身份与 FTS 迁移完成状态 | 多记录同序号、同 ID 异归属、每个迁移边界中断 | 备份先行；迁移状态可诊断；禁止丢弃原始事件 |
| PR-05 | F11/A01：版本化 enrichment patch 与有界队列 | supersede/delete/冷移期间迟到回复、stream 永不结束 | 确定性归档不依赖模型；关闭 enrichment 可正常工作 |
| 私密 PR | 维护者安全清单 | 依据私密报告的合成回归及删除/权限语义 | 修复及维护者确认后，再决定公开披露内容 |

这些 PR 不同时改检索权重、不改变默认模型列表、不重排全仓格式。必要的字段/迁移应限制在受影响状态，不趁机创建第二套数据库。

### 4.2 状态与迁移验收

补充 `recordRevision`（或等价单调版本）与索引 generation。patch 接受 expectedRevision，不匹配则返回结构化冲突；不要自动重试到覆盖成功。空 postings 也记录构建完成。canonical event 的归属键和序号必须可在迁移后验证。

恢复测试使用临时合成库，在写文件、写事务日志、提交数据库、删除日志、迁移 FTS、复制备份、切换恢复目录等边界注入故障。测试需要分别记录：进程中断、I/O 错误、权限错误、空间不足。断电测试是另一个试验类别；没有断电结果就继续明确“不保证最近事务在断电后保留”。

**R1 退出门：** 已确认的 P1 不得留下“测试偶尔通过”的状态；每条新增回归连续多次结果一致，所有原有核心套件仍通过，至少一个无 stub 安装路径成功，旧备份和旧数据库具有明确升级/回退方案。私密安全问题由维护者单独验收，不能在公开表格里用模糊“安全通过”代替。

## 5. R2：让上下文真的有界、可定位、可正确续用

### 5.1 窗口组合与位置保真

修复 F02–F04。建立一个窗口输出 schema，最少返回 selected/omitted/missing 页及原因、准确或估算的 token 数、source record ID、event/block 顺序、是否节选、正文校验和与预算状态。保留已有实现，先统一数据边界，不引入复杂消息总线。

顺序采用可比较的元组，禁止 timestamp 与局部 sequence 混作一个数字。tool-call/result、schema/arguments 与对应结果保留依赖；不能只为了塞满窗口拆开依赖而没有明确标记。强制页仍经过可见域检查，过大内容必须按硬预算规则拒绝或节选。

### 5.2 客户端接入矩阵

| 维度 | 最小验收组合 |
|---|---|
| 运行环境 | 精确声明的最低 Node 24 minor、另一个受支持 Node；Linux/macOS；Windows 未验证就不宣称支持 |
| Core/MCP | 真实 stdio 初始化、协商、工具列表、write/search/open/status、退出/重启；无测试 loader |
| Claude | 项目/用户配置、同项目两个窗口、PreCompact、Stop、重启；hook 与 MCP 私有 session 绑定必须独立验证 |
| Codex | 项目 AGENTS 与全局 config 同时存在；工作目录切换；不固定错误项目，不覆盖已有 MCP 项 |
| DSH | 固定实际宿主版本，使用有效 bundle 配置；归档、超限窗口、恢复、UI 长正文与快速切换 |
| 权限模式 | 只读/正常/维护（若新增）；显式执行 allow-list，而非依赖工具未展示 |

客户端与宿主版本写进 run manifest；“同为 MCP 客户端”不等于每个配置格式和 hook 都兼容。Claude 的 L2 绑定如暂时没有可信 host seam，应保留限制、提供明确的恢复导出路径，而不是复用所有会话的固定命名空间。

### 5.3 观察性与成本

优先本地、无正文的计量：请求 ID、任务/会话 ID、操作、模型/版本、开始结束、状态、来源版本、候选/选中/注入 token、usage 是否已知、charge 是否已结算。正文、提示词、凭据和完整文件路径默认不进入指标日志；按最小需要使用本地不可逆标识。

摘要、查询扩展、重试、模型选页的费用都归属同一任务。`attempted != succeeded`；`reported price != paid charge`；`UNKNOWN != 0`。工具时延与模型时延分开，缓存命中/写入与普通输入分开。

**R2 退出门：** hard 预算在真实宿主注入前也成立；原文引用可打开且分页无缺字；更替状态不反复复活；每个实际调用可在账本找回。未验证宿主不进入已支持列表。

## 6. R3：预注册的真实任务价值验证

### 6.1 要回答的研究问题

| 假设 | 主要观测 | 能证伪它的结果 |
|---|---|---|
| H1：Memex 比简单检索更有用 | 同模型同预算下的可执行任务完成率与人工正确性 | 只胜过近期尾部，不能胜过简单关键词检索；或收益完全来自多给 token |
| H2：有选择地不召回可降低开销 | 空库/无历史依赖/新任务时的工具与额外输入成本 | 为了使用记忆增加无效搜索、注入和读文件，质量没有收益 |
| H3：版本与状态机制减少陈旧结论 | 冲突/改需求/撤回决定的错误延续率 | 召回陈旧结论导致回归，或状态字段无人正确维护 |
| H4：跨会话保留比普通 handoff 更有效 | 新会话完成任务的质量、必要证据使用与成本 | 传统 handoff 已足够，Memex 只是重复阅读；观察到 open/cite 但非必要 |
| H5：上下文层有全任务净收益 | 质量非劣条件下的实际总费用/成功任务 | 单次调用省 token，但 capture、压缩、重试和维护抵消收益 |

成功使用一次 memory 不等于任务受益；一条 citation 也不能证明内容准确或因果必要。

### 6.2 数据与任务分层

首先用 12 个新任务作为**管线 pilot**，只检验 runner、隔离、计量、验收脚本和人工评审流程，不混入确认性效果估计。随后根据 pilot 中的方差、配对不一致率、项目内相关性和业务允许的差异，预先做功效分析确定主试验样本量；30 或 50 只是可能的探索规模，不应写成“足以证明”的固定数字。

主任务至少包含：多会话工程继续、版本/需求变化、需要早期决定的排错、无需记忆的负对照、无答案/不能推断的问题、相似但不相关的干扰，以及中文/英文真实表达。公开历史 issue 可作为一类来源，但不能全部依赖已经公开答案的问题；时间截面必须冻结，不能把后来修复混入早期 source snapshot。

按 **project、session、record 和时间** 分割训练/调参/最终 holdout。共享同一历史记录的模板问题不得跨 split。每个 split 保存 immutable manifest 与 SHA-256；人工修标签必须记录版本和原因。保留独立、从未用于调权的最终集。

可补充官方 [LongMemEval](https://github.com/xiaowu0162/LongMemEval) 与 [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2) 的适配实验；执行前固定数据/代码 revision、检查许可与所需输入模态。V2 的历史轨迹/环境知识任务可扩展覆盖，但它不是本项目实际工程交付的替代验收。公开 benchmark 也有训练污染与领域不匹配风险，结果单独报告。

### 6.3 对照组

固定同一 solver 模型及版本、工具权限、源快照、计算/时间上限与问题表达；每个任务的组别顺序随机，持久化目录和会话完全独立。

- **A：原生工作流。** 正常近期窗口、合理压缩/交接文件与可用源码工具；不人为做成一个无法解决任务的弱对照。
- **B：简单检索。** 相同历史与 token 预算的关键词/BM25 检索，保留原文引用；这是核心增量价值对照。
- **C：规则 Memex。** 修复后的 capture/search/pager/materializer，默认不使用学习型选择器。
- **D：可选学习增强。** 只在 R5 候选就绪后作为新的已注册试验，不能事后把表现好的 D 替换 C。

另设 **oracle evidence 上限**作诊断，明确告诉读者它有真值信息，不能计入产品分数。普通检索 miss 必须继续为 miss，不能从 target ID 回填答案。另可用等长无关证据排除“只是多了提示 token”的解释。

### 6.4 判定与统计

主指标先选一个，例如**在冻结验收测试及禁止副作用检查下完成任务的比例**。安全/陈旧信息错误作为不可忽略的共同约束；检索 hit@k、MRR、nDCG、引用精确率、上下文 token、p50/p95 时延是诊断指标而非生产成功的替身。

真实代码任务执行既定检查并检查非目标修改。语义任务由至少两名独立、对组别尽量盲的人工评审，分歧按预注册规则裁决。AI judge 可做辅助与扩展筛查，但不得独自决定“生产正确”。保留 judge 分歧、失败和覆盖率。

以任务为配对单位，并按项目/来源聚类估计置信区间；不把每个 token、每次调用或同一 issue 的多轮当独立样本。对主要假设使用预先选择的配对检验/cluster bootstrap。多个任务层或策略探索要调整多重比较或清楚标为探索，不从几十张图中只公布最好的一张。

非劣界值必须由任务风险和实际可接受损失确定，并在看正式数据前冻结。例如，低风险任务可讨论“完成率下降不超过 2 个百分点”，但这只是候选门槛，并非本审查认定它足够安全；高风险任务应更严格。若置信区间太宽，应报告证据不足，不能用均值相近替代非劣成立。

所有已分配任务进入登记：中断、超时、计费失败、缺评分均有分母。pipeline pilot 的淘汰与正式试验的缺失处理分开。预注册意向处理主分析与合理缺失敏感性分析；事后补跑/换 judge 另列，不覆盖原始失败。任何中途检查或提前停止规则要预先约定。

### 6.5 真正的成本账本

对每个 task/arm 建立：

```text
C_task = solver 所有尝试 + capture/enrichment + query expansion/rerank
       + retry/continuation + cache read/write + tool/infrastructure 分摊
       + 必需人工维护成本（单独列出）

质量通过后的效率 = 总实际费用 / 符合验收条件的成功任务数
```

保留实际币种、渠道、模型身份来源、价格时点与 request ID 对账。无法归属具体 arm 的账户窗口金额只能作总体佐证，不用于 arm-level 节省结论；套餐额度不能自动视作真实边际成本为零。UNKNOWN 费用给出覆盖率和可合理界定的敏感性范围，不伪造精确总价。

**拟定研究发布门：** 无确认的质量退化，且成本比的预注册置信区间支持实际净收益，才能使用“降低任务成本”宣传；仅 token 减少时只陈述 token。若没有优势，应保留可安装产品的小范围用途，收缩不必要自动召回，不用更多训练掩盖结论。

## 7. R4：性能优化必须有预算、有失效模式

先修 F10/F16，然后测量是否还存在瓶颈。性能基准固定机器、Node/SQLite/文件系统、数据生成 seed 与冷热状态，至少覆盖 1k/10k/100k 记录、0/50/90% 冷记录、短/长正文、中英文与混合标识符、并发 1/4/16、多进程写入，以及备份时的查询。

分别报告启动时间、文件读取数、CPU、RSS、event-loop lag、锁等待/持有时间、检索 p50/p95/p99、materializer 延迟与输出预算违例；报告稳态与首次启动，不只给 warmed-cache 平均值。原先“100M token 容量”与测量的实际 bytes 必须分别记录，递归统计磁盘文件。

优化顺序：索引完成标记 → 增量变更 → 去除重复读取/渲染 → 简单候选预筛 → 有界缓存 → 必要时 worker。缓存键包括 source revision/scope/query/policy，过期与删除会失效；不要引入隐形、跨工作区的持久认知状态。性能变化与检索质量一起比较。

可以先提出特定参考机上的候选目标（例如 warm search p95 ≤50ms、cold search p95 ≤150ms、1,800-token 窗口组合 p95 ≤30ms），**这些是待批准、待测的工程目标，不是当前性能或跨硬件承诺**。在低配机器先记录基线，再调整目标；不能为了满足时延阈值默默少搜、遗漏必选页或降低隔离标准。

## 8. R5：学习型选择器的最小研究路径

### 8.1 先研究选择问题，不直接训练整个记忆系统

输入是冻结候选页、当前问题/任务状态、允许 token 预算；输出先只做相关度/必要性打分。先比较词法基线、校正后的混合规则、现成小型 cross-encoder，再决定是否需要微调。保留 rule-only 回退，不把 learned 作为写入权限或事实判定权。

候选池固定以隔离“召回是否找到”与“重排是否选对”；另做端到端检索实验。标签应区分 relevant、necessary、stale、contradictory、unsafe-to-inject、irrelevant。多份相似摘要、版本更替、错误假设、中文同义改写和无答案问题应作为 hard negatives。

### 8.2 数据与验证

去除 record/session/project 泄漏；至少多个预先固定 seeds，报告每次结果而不是只选最优。保持最终 test 完全不可用于提示词和权重修改。记录标签者一致性与无法判断样本；不把模型自己生成的标签当作独立真值。

在固定窗口预算下比较 evidence recall/precision、遗漏必要依赖、陈旧内容率与最终任务成功。必须加上“可以什么都不选”的 calibrated abstention；学习到一律多选不是有效上下文策略。

### 8.3 部署与停止条件

优先 CPU、小批量、top-k rerank，测包括模型加载与 tokenization 的总成本；缓存不得跨 scope。只有在项目隔离 holdout 和真实任务 canary 都达到预注册改善，且成本/尾延迟可接受，才默认启用。若简单规则达到相同质量更省资源，就保留规则；若收益只存在于模板数据或一两个项目，研究结论就是不泛化，不继续堆大型模型。

窗口 assembler/pointer policy 可作为后续独立问题，但先用确定性 budget packer 作强基线。允许模型建议排序，不允许它绕过 token hard cap、来源标签或工具依赖完整性。

## 9. K：原生 KV/offload 支线

### 9.1 优先上游能力对照，减少长期维护负担

先修 F05 的接口不一致。然后固定模型 revision、tokenizer、vLLM 版本、硬件与精度，比较：无缓存、native prefix cache、上游 KV offload、Memex thin-adapter/hybrid。参考 [vLLM KV offloading](https://docs.vllm.ai/en/latest/features/kv_offloading_usage/)，执行时重新固定具体版本，不能用 latest 文档推断旧 0.10.2 原型兼容。

如上游已经提供相同的存储/恢复能力，优先使用上游 connector，仅保留 Memex 的上下文页选择和映射，避免持续维护 debug 实现的分叉。`native hot first` 是待实验的合理方向，不是“外置更快”的保证。

### 9.2 正确性先于速度

完整 cache identity 包含模型/权重 revision、tokenizer、chat template、精度、RoPE/位置参数、adapter、分片布局、上下文前缀内容与租户身份。租户身份必须来自可信宿主，不接受提示词自行声明。固定前缀才允许复用；任意重排文本页不能直接拼接旧 KV，因为位置和注意到的历史可能已变化。

清单覆盖全部预期层、shape/dtype/长度与校验和；原子发布完成状态；读取期间有占用保护，不被逐出；部分/损坏/版本错配转为明确 miss 并重新计算。短前缀、prefix_tokens=0、多模态、LoRA、多卡及指定 CUDA device 都有测试，未覆盖就明确不支持。

### 9.3 性能实验矩阵

前缀长度 128/512/2k/8k，缓存冷热、重启、显存压力、SSD 速度、并发 1/4/16/32；用每种条件预先固定的重复次数和随机执行顺序，报告方差及 bootstrap CI。度量 TTFT、总响应时间、decode throughput、GPU/CPU/RSS、磁盘 bytes、命中率、首次 store 开销与恢复失败率。不要只报“第二次命中快了多少”。

数值一致性用同输入/配置 direct 与 paged 输出对比，报告最大/分位 logit 差异、next-token 一致性与长解码质量；容差按精度预注册。某次 0.0 差异只能支持该次配置，不能外推所有模型。

简化的经济决策：`命中次数 × (重算成本 − 加载成本) > 首次存储成本 + 维护/逐出/失败回退开销` 时才有潜在净收益，最终仍由混合工作负载验证。热前缀 native 更快就让 native 处理；短前缀重算更省就不外置。若上游方案全面更好，终止自有 connector 产品化，保留研究记录。

## 10. 研究登记与发布规范

每次新实验一个目录和机器可读 manifest，最少含：hypothesis、registeredAt、code commit、data hash/split、task IDs、模型及供应商身份来源、配置与随机种子、主指标、接受/停止规则、调用/金额上限、实际尝试账本、缺失/排除/补跑原因、审查者与统计代码版本。登记内容先提交，结果追加，不修改原登记掩盖偏离。

付费或 GPU 实验需独立批准总费用上限与超限停止策略；本次审查未启动这类实验。当前可马上执行的下一步是修复与离线验证，不需要先租 GPU 或训练模型。

每个实现 PR 模板：

```text
关联问题/假设：Fxx 或 Hx
受影响范围与未改变的行为：
修复前最小复现：
设计取舍：
新增/原有测试结果：
迁移、回滚及老版本兼容：
隐私与额外模型费用变化：
剩余限制：
```

发布硬门：无未处置 P1；新老数据升级/回滚有验证；默认操作边界与文档一致；受支持客户端真正启动；预算/事件顺序/作用域不变量通过；公开声明仅使用本版本能追溯的数据。推广和性能优化不能抵消安全或数据完整性失败。

## 11. 最终决策框架

**先让数据可信、调用可用，再让上下文值得注入。** Memex 的竞争点不应只靠“外部池容量大”，而应靠：能证明来源与版本、避免无用读写、在复杂长任务中提供决定性上下文，以及让用户清楚知道数据如何保留和撤回。

当证据显示某类任务有效，按该类任务逐步开放；没有收益的场景保留最简原生工作流。成功的迭代允许删除无价值复杂性，也允许研究得到负结果。生产主线与研究支线分别发布，才能既保持探索，又不把用户的工作当未经验证的实验。
