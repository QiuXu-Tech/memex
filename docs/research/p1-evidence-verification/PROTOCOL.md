## 2. 可见性边界：公开任务、控制器与 evaluator

### 2.1 三域隔离

| 域 | 可以持有 | 不得用于该域的方法决策 |
|---|---|---|
| Agent-public | 自然用户请求、可观察的行动提案/答复草稿、公开工具说明、当前工作目录、原生压缩后可见上下文、按既有权限可见的原始归档及原生来源元数据。 | 答案键、gold 声明清单、正确源 ID/offset、预定测试结果、人工“最新/相关/支持”标签、隐藏检查结果。 |
| Controller-only | 冻结运行清单、随机化、预算、宿主分支/公开重放信息、环境与源快照摘要、调度和失败台账。 | 根据 gold 决定检索词、证据排序、截断位置、触发、重试或是否继续某个 arm。 |
| Evaluator-only | 关键决策义务、当前状态真值、等价可接受证据集合、隐藏行为检查、独立性/聚类台账、标注与裁决。 | 在运行封存前向方法提供补漏提示、正确候选或评分反馈。 |

部署进程只接收白名单构造的 public 输入，不能读取完整 case 后再删除几个私有字段。原始归档由宿主事件自动捕获；索引不能从 evaluator 的语义标签生成。三个域需通过挂载、进程权限和工具端点隔离，不能仅把 `private/` 放在相邻目录并要求模型不读。

[study-manifest.schema.json](schemas/study-manifest.schema.json) 与 [run.schema.json](schemas/run.schema.json) 是 **controller/evaluator 的研究输入契约**，不是 agent-visible task schema，也不能整份注入模型上下文。

### 2.2 方法输入的具体要求

- 不使用历史驱动的 `case.claims` 作为正式方法输入，不按 gold 的 `[type, scope, entity]` 精确过滤，不固定 `eventIndex=1`。检索与打开跟随实际返回的动态 locator、分页 cursor 和原文字节摘要。
- 候选声明从自然请求及可观察状态自动抽取，保留原文 span、实体/范围、候选值和未解决字段。当前版本可能正是待发现的值，因此允许 `target_version=null`。未知字段不能由 controller 从 gold 补齐。
- C/D 及其他声明驱动对照共用抽取器与预算；A 不消费其输出。后续各 arm 的观察已经不同，不能继续假装共享同一抽取结果。抽取漏报仍以 evaluator 冻结的全部关键义务为分母。
- 公开来源元数据可包括原生角色、主体、工具调用 ID、对象 ID、事件序列、时间、哈希、完成状态及自动绑定的制品摘要。正文自称“owner decision”不构成原生用户身份；人工填入的 `supports_claim`、`is_latest` 不得冒充捕获元数据。
- 从自然日志解析出的类型字段必须有可运行规则和来源 span；解析错误计入端到端结果。日志退出码为零本身不证明目标测试已执行且通过。
- 历史授权只作为实验事实。任何受限动作在本地 simulator 中记 attempt/accepted 日志，不进行真实部署、删除、付款或外部通知。

## 3. 任务采集与隐藏行为

### 3.1 八个开发槽位

| 槽位 | 必须覆盖的工作状态变化或失败模式 |
|---|---|
| D01 | 旧制品通过后修改相关代码，必须对新制品重测；配一个无变化、允许复用的分支。 |
| D02 | completed/pass、cancelled、NOT RUN、零断言和无关命令退出零的区别。 |
| D03 | 题干不给正确版本，从真实 readback 发现当前版本并绑定实际制品。 |
| D04 | TTL 内的旧 grant 被归档中的新 revoke 撤回，必须禁止模拟动作。 |
| D05 | 原生主体、assistant 自述、工具正文伪造授权、相邻对象/范围授权的区别。 |
| D06 | 乱序到达、多源冲突、原生 revision/sequence 与不可靠 wall-clock 的区别。 |
| D07 | 可变事件位置、跨页长日志、截断及缺失完成标记。 |
| D08 | 自然请求的多项义务、否定约束、无关陈述及抽取遗漏；不能靠空候选数组过关。 |

这些槽位可以使用合成材料验证程序行为。每个槽位的反事实变体属于同一任务家族，不能增加独立 N。开发任务包需包含公开输入、环境、原始事件、私有义务、隐藏检查和可重算运行记录，不能只交一条 gate 单元测试。

### 3.2 十六个真实先导槽位：全部待采集

| 槽位 | 采集目标 | 拟议数量 |
|---|---|---:|
| P01–P04 | 真实仓库修复、后续状态更新、重测与本地 review 工作流。 | 4 |
| P05–P08 | 真实制品、配置或接口版本变化，以及权威 readback。 | 4 |
| P09–P12 | 真实仓库本地工作加明确标注的模拟 review 授权；含有效、撤回或范围不符状态。 | 4 |
| P13–P16 | 至少两类义务相互作用、冲突或可判定缺证的工作流。 | 4 |

每个可纳入任务必须满足以下采集条件：

1. 有独立 upstream issue/source-event workflow 和固定仓库 revision；后续决策确实需要早先证据，且至少一次相关工作状态变化发生在流程中。不能先完成全部代码，再只做证据问答。
2. 真实来源、人工注入状态与 simulator 部分逐项标明。目标覆盖多个仓库，拟争取至少 8 个；仓库数量不是统计有效性的保证。
3. 记录仓库、upstream issue、关键源事件与工作流家族。共享决定性上游事件的变体不算独立任务。按这些家族整体分开发、先导、确认和外部集，避免跨集污染。
4. 建立代码、issue、文档和日志的来源及许可台账；公开可读不等于允许再分发。私人材料需明确研究授权，许可不明材料不进入发布语料。
5. 冻结可回答任务与正确弃答任务的分布。不能根据各 arm 的初步成绩修改正负例比例或排除不利任务。
6. 在不接触方法输出的情况下，由两名具备能力的评估者独立标注关键状态和义务，完成分歧裁决。

采集台账至少保留 `acquisition_status`（`not_acquired/acquired/validated/frozen`）、源 URL/commit、许可、真实/模拟成分、独立性分组、public/gold 哈希、环境重建说明、前置轨迹、压缩收据、隐藏检查、标注者与裁决。全部验收后才把槽位计作可用任务。

### 3.3 隐藏行为必须发生在取证之后

主要检查包括：必要测试真实执行且晚于最后相关写入；测试与模拟提交绑定同一制品摘要；实际选择的版本满足当前权威状态；撤回后没有受限动作尝试；证据充分时完成必要工作；确实不可知时正确不行动并说明欠缺。

simulator 的底层拒绝不抹去违规 attempt。单纯说“已重测/已选正确版本”不能替代执行日志。新运行产生的有效证据可以支持答案，评分不能只接受预定旧 source ID。隐藏运行器不可用须记测量故障，不能自动判通过或删任务。

## 4. 比较臂、共同前置状态与预算变更

| Arm | 作用与冻结要求 |
|---|---|
| A Native | 原生继续执行参照；共享自然请求、前置状态和当前工具权限，不注入附加 gate/抽取结果。 |
| B Strong Raw-RAG | 实际 dense 检索、重排及原文呈现；固定官方 commit、模型、prompt、去重、完整轮次展开和预算装配。旧 forced gate 不能改名作为 B。 |
| C Always verify | 对全部候选运行与 D 相同的取证、解析、状态验证和交付核心；批处理/去重优化一致。 |
| D Selective | 仅当复用证书有效时跳过昂贵重取；否则执行 C 的同一核心。 |
| T TierMem 候选 | 新增近邻方法候选；先冻结可复现实现、忠实性检查、覆盖子集/全量和成本。尚未完成忠实复现，不能把自建近似直接命名为原方法结果。 |

其他 E/F/G/H 消融、oracle 或治理对照按正式设计登记，不因加入 T 而默认被替换。T 的文献与比较动机见 [论文工作稿](manuscript.md) 和 [参考文献](references.bib)；本协议不宣称已复现其效果。

当前 [Raw-RAG 配置](../../../scripts/paper1/rawrag-config.json) 的 `query_policy` 是 `original_request`，属于忠实原始请求路径。若另做使用自动声明扩展查询的 B，必须作为适配配置另行冻结，记录相同抽取器的成本；不能声称当前 faithful B 已消费声明。预算匹配版与官方完整呈现版若不等同，应分别运行和记账。依赖/权限缺失时保留阻断状态，词法诊断不能替代强 B。

每个 task×replicate 先建立共同前置轨迹，穿插真实工具工作、状态更新和原生压缩，再从同一可验证环境/宿主状态分出各 arm。使用公开支持的分支或重放能力；不能修改私有宿主状态。无法可靠分支时，明确标为冻结轨迹续跑，并重新核算前置成本。不同独立前置轨迹是另一种实验设计，不能描述成完全同源配对。

**原预算必须重新冻结。** 原四臂先导算例为 `16×4×2=128` 次续跑，若可共享前置状态则另有 32 次前置执行。T 若加入全部先导任务，新增 `16×1×2=32` 次续跑；加入正式 N 任务则新增 `2N` 次。其建库、路由、前置轨迹和依赖成本也须计算。覆盖子集、无法分支或更换原对照时重新列完整运行清单；这些运行次数不增加独立 N。旧资源总额不能直接当作当前设计已批准预算。

## 5. 证据复用与 freshness 的最低条件

跳过重取之前，必须已经建立适用 scope/lineage 的完整状态覆盖，或取得真实权威当前 readback；随后检查源视图、当前对象、规则版本和时间条件仍有效。证书保留原文字节/摘要、来源身份、对象/范围、制品绑定、验证规则版本、完整视图水位和有效期。

稳定归档 head 只表示没有新增归档变化，不能证明首次 top-k 没漏掉同一 head 中已有的撤回。搜索到 grant 且没搜到 revoke 不是完整生命周期证明。可先采用保守全局 `(epoch, sequence, root_hash)`；实体级水位需要可审计解析与覆盖证明，不能由 gold 相关性提供。

head、epoch、对象 digest、parser/policy revision 或有效期改变时，获取完整 delta 并重放/重建，或者返回无法核验。通知缺失、捕获缺口、重启后状态不明、分页不完整及权威来源冲突均不得默认为 fresh。保证只针对已摄取且明确截止水位的源视图，不覆盖未知外部变化。

撤回、替代、冲突、通知丢失、乱序、重启六类反事实必须通过开发验收。D 的缓存读取、证书校验和原文重新交付都计成本；缓存的 `verified=true` 不能替代可审计证据。

## 6. 冻结单位、主要终点与统计

### 6.1 任务级成功与完整分母

对任务 i、arm a、重复 r，`Y_iar=1` 仅在全部冻结关键义务满足、隐藏行为通过、关键肯定有适用来源支持且无错误高影响肯定时成立。可回答时无谓弃答、遗漏必要动作或未运行却声称通过均为失败；确实不可知时合理弃答并正确行动可以成功。

接受等价可解析引用和等价有效支持集合；不能凭 sourceRef 字面不相等或英语措辞正则判事实错误。事实正确、来源有效、实际原文送达与遥测可观察性分开报告。未知内部遥测不自动证明使用过或没有使用归档。

冻结 manifest 的 `(task_id, project_id, arm, replicate)` 是唯一运行键。分析从 manifest 左连接原始 JSONL；缺失、超时、合法方法失败和无效输出不会被移出分母。一个 task 只能归属一个 `project_id`。当前分析器拒绝重复键、未计划运行、非首次 `attempt` 或非空 `retry_of`，不会择优选结果。

先按每任务每臂的全部已计划 replicate 求均值，再计算任务配对差：

`Ybar_ia = mean_r(Y_iar)`；`delta_i(DB) = Ybar_iD − Ybar_iB`。

报告任务平均差。声明、种子、压缩边界、重复运行和反事实变体不增加 N。计划本身缺少某个对比臂时报告 `unpaired_design`，不能偷偷只分析完整配对子集。

### 6.2 项目聚类与区间

当前 [analyze.py](../../../scripts/paper1/analyze.py) 对 `project_id` 重采样，再在被抽中的项目内重采样任务，最终按任务平均；任务级 bootstrap 仅作忽略聚类的敏感性分析。共同上游事件跨仓库时，应先确定能反映依赖的抽样簇并保留原仓库映射；无法用单一层级表示的交叉依赖不能被当前实现自动解决。

使用固定 seed、95% 双侧 percentile 区间，并记录 NumPy 版本。默认 `min_tasks=20`、`min_projects=8` 只是可配置的 operational guard；正式协议必须明确冻结实际值。它们**不是已经注册的门槛、功效计算或覆盖率定理**。输出保留 `guard_not_power_analysis=true`。少于 1,000 次 bootstrap、任务/项目不足或经验 bootstrap 退化时不据此确认效果。

16 任务先导用于可行性、失配率、方差、失败率和资源估计，不能单凭无显著差异确认 3 个百分点非劣。正式 N、效应与非劣界限的实质依据及 H1/H2 检验层级须在正式结果解封前完成独立统计审阅；资源不足时收窄主张或延期。

### 6.3 H1 → H2 门控

`development`、`pilot`、`external` 在当前入口中均只作描述。确认性标签还要求 `study_phase=confirmatory`、manifest 与 `analysis_plan` 明确冻结、实际生效设置一致、输入/采集完整性问题已解决和主区间可推断。

- **H1：** D−B 质量差的 95% 双侧区间下界严格大于 0。
- **H2：** H1 已成立；D−C 质量差区间下界严格大于 −0.03；完整冻结的全流水 `C_std` 费率/分摊信息可用且相关计划运行的成本无缺失；D−C 成本差区间上界严格小于 0。四个条件缺一不可。

实现使用 `1e-12` 的保守浮点容差，等于边界不通过。非劣不等于完全等效。冻结值与 CLI 覆盖值不同会降为描述性；`frozen:true` 本身不能证明真实的预注册时间、标注独立性或费率完整性。

## 7. 全流水成本与质量必须分开

统一参考费率下，`C_std = Σ usage_j × frozen_rate_j`。成本范围包括共同前置工作、原生压缩、抽取、查询生成、embedding、reranking、原文打开、类型解析、freshness 元数据检查、证书校验、缓存读取/写入、证据重新交付、reader 输入/输出、CPU/GPU、存储以及纳入当前执行策略的失败操作。零调用数不是零总费用。

费用台账记录模型/供应商/版本、费率来源/日期/币种/单位、非缓存输入、缓存子项、输出、实际调用、CPU/GPU 秒、字节×时间、延迟和请求 ID；明确 provider 总输入是否已经含缓存，防止重复计价。未知计量或未知价格填写 null/缺失原因，不能补零。

共享 prelude 或抽取在部署估算中按每 arm 每任务一次计入；研究实际支付只记真实发生的次数。一度建库的摊销工作负载、分摊规则和敏感性范围预先冻结。实际支出按币种单列，不能拿实际账单替补 `standardized_cost` 或与其混算。

`cost_model` 要提供 `frozen`、`currency`、`rate_card_id`、非空数值 `rates`、`cost_scope=full_pipeline_per_scheduled_task` 和 `allocation_rule`。完整组件账本和费率来源另行封存。当前分析器只审查提交的总额及声明，**不会从未提供的 usage 重算成本，也不能认证账本覆盖了所有组件**；人工成本审计仍是 H2 门槛。

### 已修复的关键统计约束

| 记录情形 | 质量处理 | 成本/确认处理 |
|---|---|---|
| `completed` 且质量 bool 有效，只有成本损坏 | 保留原质量结果，不改成失败。 | 成本为 null，单独 `invalid_standardized_cost`；不得由成本损坏创造 H1 增益。 |
| 未知 status 或 `completed` 的质量字段不可读 | ITT 暂计 0，保留计划分母。 | `data_issue.blocks_quality_confirmation=true`，阻断确认并等待修复/裁决。 |
| 预定义真实方法失败，如 `model_invalid_output` | 正常 ITT=0。 | 不把真实方法失败当成可排除的数据损坏；已有费用照计。 |
| 费率字段损坏 | 不改变质量均值、区间或 H1。 | 冻结成本模型条件不成立，不能支持 H2。 |
| JSONL 行不能解析/定位 | 对应缺失计划运行仍留在分母。 | 保留 `input_issues` 并阻断确认，不能只挑可解析的有利样本。 |

对应回归见 [统计测试](../../../test/test_paper1_analysis.py)。这些回归使用合成输入验证评分器，不是论文效果数据。

## 8. 当前分析入口与 schema 的使用

所有命令从仓库根目录执行。以下两个命令只检查本地程序，不运行模型：

```bash
python -B scripts/paper1/analyze.py --help
PYTHONDONTWRITEBYTECODE=1 python -B -m unittest discover -s test -p test_paper1_analysis.py -v
```

真实运行清单与原始 JSONL 采集、冻结后，使用实际文件路径：

```bash
python -B scripts/paper1/analyze.py \
  --manifest /absolute/path/frozen-manifest.json \
  --runs /absolute/path/first-attempt-runs.jsonl \
  > /absolute/path/analysis.json
```

该命令不生成任务或研究记录；stdout 是 JSON 报告。重复计划/运行、未计划运行等致命输入错误返回 JSON 错误和退出码 2。退出码 0 只表示完成审查，不表示 H1/H2 成立，须检查 `hypotheses`、`input_issues`、`data_issues` 和所有状态分母。

一个用于声明“尚无数据”的最小开发 manifest 结构是：

```json
{"schema_version": 1, "study_phase": "development", "frozen": false, "runs": []}
```

它不代表已经采集任何任务。不要为了让示例完整而填假结果、假来源或假价格。

### 需明确冻结的分析字段

| 位置 | 字段/要求 |
|---|---|
| 顶层 | `schema_version=1`、`study_phase`、`frozen`、完整 `runs`。 |
| `analysis_plan` | `frozen`、`primary_contrast=D-B`、`secondary_contrast=D-C`、`confidence_level=0.95`、`noninferiority_margin=0.03`。 |
| 统计设置 | `bootstrap_method=project_then_task_percentile`、`task_weighting=equal`、`replicate_aggregation=mean`、`seed`、`bootstrap_samples`、`min_tasks`、`min_projects`。 |
| 每条运行 | 四元键、`status`、`decision_success`、`standardized_cost`；遥测、实际支出、版本和台账引用可另填。 |

不传 CLI 覆盖参数时入口使用冻结的 seed/重采样次数；缺失设置使用开发默认值并阻断确认。当前 schema 是规范化记录的 authoring contract，JSON Schema 检查还不能替代跨行键唯一、项目一致性、源完整性或独立性检查。

**schema 验证失败不能成为删例规则。** 保留原始行及错误台账，将完整文件交给分析入口审查。特别是成本字段格式错时，质量可能仍然可用；不能预先过滤整条运行。分析输出不复制所有可选 token/来源遥测，原始 JSONL 与配套账本必须永久保留。

## 9. Failure ledger 与重试

每个已计划执行单元都必须有终态或明确缺失原因。ledger 至少绑定四元键、run/attempt ID、阶段、时间、host/model 版本、失败类型、原始日志/哈希、是否产生可判读终答、用量/费用及其缺失原因、重试关联和人工裁决。

| 状态/问题 | 当前处理 |
|---|---|
| `completed` + 有效 bool | 使用 evaluator 给出的任务终点；false 是失败。 |
| `failed`、`host_error/host_failed/host_failure/host_timeout`、`provider_error`、`prelude_failed` | ITT=0，保留真实费用和原因；不从配对中删除。 |
| `model_invalid_output`、`budget_exhausted` | 方法/策略失败，ITT=0；不升级成可排除基础设施错误。 |
| `running`、`not_dispatched`、缺失运行 | ITT 暂计 0；采集未结束，阻断确认。 |
| `capture_incomplete`、`evaluator_error`、未知状态/不可读质量 | 保留记录与分母，阻断确认，不能假装有可信评分。 |
| D/C 对比所需成本缺失/损坏 | 保留有效质量；相应成本均值和区间不可建立，H2 成本门槛不通过。B 的成本问题另列，不得改变 D−B 质量。 |

`scheduled` 属于计划/调度 ledger，不是当前 `run.schema.json` 中可作为完成结果提交的状态。适用状态必须在采集前明确解释，不能将未知日志随意改成 `model_invalid_output` 以绕过数据完整性阻断。

**当前主分析是首次尝试策略。** 不接受重复键或第二次 attempt，不自动合并重试。诊断性补跑保留原始失败与全部实际支出，另表列出。若正式研究要使用“允许有限基础设施重试”的部署策略，必须在采集前修改协议、成本归属、实现及测试，并重新冻结；不能把目前首次尝试分析冒充含重试的全流水比较。

观察到 host/model 漂移、配额阻断或系统性捕获故障时暂停该 block，建立有版本说明的新分层。不得用新版本补成功结果后与旧失败混成同一未说明配置。

## 10. 人工复核与进入下一阶段的门槛

关键状态由独立双标产生；复核全部组间不一致案例和预先随机选择的 20% 一致案例，尽量对 arm 身份盲评。模型评审只能辅助定位，不能替代行为、原始来源资格和当前状态裁决。实现者不能独自裁决争议标签；保留原标签、分歧、理由及裁决版本。

### 开始真实先导之前

- public/controller/evaluator 隔离通过可观察检查；删除预设声明和正确定位依赖；自动抽取失败能够被终点评分捕获。
- 8 个开发工作流任务包验收；六类 freshness 反事实与分页/来源权限/制品绑定回归通过。
- 强 B 的真实实现、依赖、访问能力、reader、原文呈现和成本可运行且通过忠实性审查；T 与治理对照的是否纳入、范围和替代命名已登记。
- 16 个新真实任务完成来源、许可、独立性、环境及双人 gold 验收；同源前置分支/公开重放得到验证。
- 冻结先导随机化、资源上限、失败/首次尝试策略、全流水成本账本和收集停止条件；执行额度与资源权限已经实际具备。

### 正式确认之前

- 完成先导质量审计及样本量/精度论证；明确 H1 与 H2 的确认/估计等级，不按观察结果放宽 −0.03 界限。
- 重新冻结包含 T、官方/匹配 Raw-RAG、消融、反事实和泛化的完整运行清单及预算。
- 冻结任务、源、标签、public 字段、提示、源码/依赖、宿主/模型版本、环境、随机化、预算、费率、评分器、统计设置和排除规则，并保存哈希。
- evaluator 留出隔离与人工责任已确认；确认集未用于调参或实现修正。发生泄漏或实质评分错误时，旧轮降为探索性并建立新确认集。

### 正式投稿之前

- 每项摘要数字能追到冻结任务分母、原始终答/行为、source qualification 与成本账本；主结果包含失败，不只报可评分成功子集。
- 无模型调用的离线重算路径可复现；强/近邻基线忠实性、不可用配置及样本/宿主局限清楚披露。
- 若 Raw-RAG 已解释全部增益、H2 区间过宽或某配置失败，按实测边界写稿；不得用 smoke 或开发用例补成正式结果。
- 人类作者复核文献原文、贡献与作者身份、数据权限、匿名、AI 使用披露和当前目标 venue 政策。投稿、支付和发布由负责人另行执行；本文档不会触发这些操作。

**完成定义：** 原始输入、冻结计划、全部运行、关键义务、评估裁决、统计与成本可以相互追溯。是否获得正向效果以及是否录用仍然开放。
