| 审查发现 | 处理 | 验证依据 |
|---|---|---|
| 成本字段损坏曾把本来成功的运行转为质量失败，可能制造虚假的 D−B 优势 | 质量与成本分别解析；坏成本保留为未知并阻断成本确认，不改变有效质量；未知质量或损坏研究记录阻断确认 | 24 任务、8 项目、72 条成功运行、18 条坏 B 成本的回归：72 次成功，D−B=0，H1=false |

| `node printer.js --test` 可能被误当真实测试命令 | 限定可支持的 Node argv 和 shell envelope；`--test` 必须是 Node 首个选项；拒绝 eval、shell 组合和未声明 executable | 命令伪装回归及真实 Node 子进程解析测试 |

| Raw-RAG 公开 source 白名单拒绝共享 Node/authorization 来源中的合法字段 | 补全共享字段；不删除来源信息来迁就基线 | 两个跨臂测试经真实 Memex L2 和 verifier，再由 Raw-RAG validator 接收 |

## 明确保留的限制

这些修复没有证明一般自由文本日志的正确归一化、真实任务 claim 抽取的完整性、多写入者 archive 一致性、任意外部变化检测或模型对证据的正确使用。当前完整视图由受信任的单写入 host observer 声明；没有 observer 的覆盖保证，核验器不能证明“不存在未见的撤销或版本变化”。

默认预算尚未构成冻结的跨臂总预算；实际 Raw-RAG 调用和供应商账单未取得；正式任务与人工义务标注未完成。审查未作接受论文或投稿准备完成的判断。

审查后发生的原生宿主协议兼容修复另有定向回归与真实运行记录。失败尝试保持可见；不删除失败轮次后只展示成功摘要。

## 第二批：实时状态、调度与真实模型接入

本轮独立审查后的定向复核实际通过 37 项调度/计量测试和 9 项 broker 测试。完整研究套件另有 65 项 Node、119 项 Python 测试，合计 184 项通过，零失败/跳过。

| 发现 | 已落实处理 |
|---|---|
| 四元任务键可能误接另一份公开输入或另一次执行的评分 | `run_id` 纳入 spec/public/runner 身份；独立 evaluator 的评分必须绑定冻结摘要和具体封存执行摘要；重新核对完整输出树 |
| 已完成模型臂可将全部组件标 N/A，得到虚假的完整零成本 | 冻结每臂必测组件，完成状态要求真实正向用量；未知量/价保留 null；合法零价需要独立依据 |
| 公开输入摘要遗漏 mode 和空目录，配对输入可能不同 | 纳入根/目录/文件类型、权限、目录条目和内容摘要 |
| broker 重启重置 source sequence，旧证据可能压过新观测 | 开发 broker 仅允许新 state/output 目录，不支持不完整恢复 |
| 任意请求可被重定向到当前目标；旧抽取可能跨准备周期残留 | 仅接受明确的当前工作区模板，绑定一次性准备输入与实时版本；开始新准备即清除旧提案 |
| 原生控制器对成功 outcome、真实 open 和版本弃答的判据不准确 | 使用实际 `supported` 值，要求非缓存真实 L2 open；旧证据必须被打开且返回明确 `version_mismatch` |
| 失败辅助调用可能漏入摘要；序列化预算与实际传入字节不一致 | 失败也保留 host trace/usage，协议等待共享截止时间，单次序列化同时用于预算、摘要和交付 |
| 首次真实提取 schema 合法却遗漏测试前提 | 保存首次失败；通用规则澄清前提也是待核验命题，并版本化为 `observable-obligations-v2`；同一家族一次复测通过，不计准确率 |

原生全链路的实际失败是宿主要求 MCP 写操作审批，而无人值守接口没有交互批准通道。此项保留为阻断，未伪造 read-only 标记、代替真人接受或修改管理控制。独立只读抽取组件的复测不能替代这一缺口。详见 [LIVE_HOST.md](LIVE_HOST.md)。

## 第三批独立审查与修复

第三批完整研究套件共 **265 项通过（70 项 Node、195 项 Python）**。下表列出的定向测试已包含在对应套件中。

| 发现 | 修复与定向验证 |
|---|---|
| 公共归档只检查 JSONL 事件的顶层字段，可在 `completion` 中嵌入 `{"gold":"hold"}` | 逐条递归拒绝评估专用字段，并拒绝在标量元数据中嵌入对象或数组。任务包测试 26 项通过，11 个已物化包均通过校验。 |
| 审批处理器原先可转发任意枚举选项，无法兑现仅限单次调用的约定 | 原型只接受两种明确的一次性问题及固定选项，要求 `isBlocking=true`，校验可空的 `autoResolutionMs` 并限制等待。遇到未知问题、持续授权或通用确认表单时停止。审批测试 12 项通过，实际宿主一次性问题形态和真人批准执行均待验证。 |
| 来源资格驱动记录了最终测试文件是否仍一致，但原判定允许文件已变的候选获得资格 | 资格判定现要求测试文件哈希保持一致。来源复现测试 18 项通过，历史执行和只读重判分别留档。 |

只读开发案例记录了 5 次生成、1 次原生压缩和从同一前缀建立的 3 个分支。A、C、D 均建议暂缓发布并引用当前失败收据。C 打开原文 2 次，D 复用证据、打开 0 次，两者的原生输入计数均为 15,350 token。此例可验证读取路径，尚不能估计方法效果或总成本。

累计 16 个来源候选均有尝试记录，12 个取得来源及环境资格，4 个保留具体限制。11 个工作流包尚未验收，22 份双审材料均为空白模板；正式先导样本与人工审阅仍待完成。
