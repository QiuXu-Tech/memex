## Native compaction

Calibration uses two held-out pilot tasks. The formal cohort contains eight executable tasks, each repeated in three arms with fresh workspaces, threads and memory roots, and three manually requested native compaction boundaries at the same task milestones. Keep the host version, actually resolved model, reasoning level and workspace sandbox common. Vary the arm order by task. Only completed native compactions in the same thread count. Determine whether exact original source text remains in the model's replacement history from the actual experiment transcript where available. Keep unknown where the host does not expose the relevant content.

A uses ordinary Codex with native compaction. B installs the study-local MCP server and may search/open captured prior sources on demand. C uses the same archive and search/open and receives one evidence reminder after each confirmed native boundary. Formal B and C share a per-turn ceiling of 4,800 UTF-16 code units (1,200 estimated tokens) for recovered evidence. C precharges the reminder against that ceiling. The study-only MCP proxy refuses a reply that would exceed the remainder, allowing a smaller follow-up request. Pilot runs calibrate the host and do not use the shared ceiling. Capture only allowed same-thread source items. Replay neither old edits nor archived commands. The task prompt, initial files, staged sources and approval scope are paired across arms. No ground-truth key is visible to a study agent.

Primary outcomes are correctness of mandatory constraints, evidence-supported completion of the code task, and unsupported claims. Score original and updated values, exact tool results, false success, UNKNOWN, and withheld authorization separately. Use held-out behavior tests and a source-checked handoff, including verification that a claimed local test was actually run. Count completion, native boundaries, tool use, time and input/output/cache telemetry separately. Retain transport errors and interrupted cases. A host failure may be diagnosed and restarted with a fresh ID only as a separately recorded attempt. Aggregate paired outcomes by task; multiple probes in one task are correlated. Report actual effects and avoid inferring a real-world rate from the cohort.

## Large archive

Persist two nested, separately queryable archives with about 10,000,000 and 100,000,000 actual body tokens under one disclosed reference tokenizer. Count the saved text instead of multiplying assigned record metadata. Record totals, disk size, hot/cold balance, input shape and write timings. Cold records, shared terms, scoped decoys, contradictory earlier receipts, and missing facts form explicit trials. Run the same preregistered software-development questions and source checks through the real Codex client and the actual local MCP server on both stores. The reported model window, model input/cache/output counters, archived token totals and visible scope are distinct quantities. Source IDs, correct values and unanswerable controls are withheld from the respondent until grading. Preserve response and tool-use receipts and give per-size quality, latency and cost telemetry. Bounded real-host results support claims only for the tested archive and workflow.

Use local compute and existing Codex allowance. No extra model API, GPU rental, archive publication, release or automatic merge. Publish synthetic scripts, definitions and aggregate evidence in one reviewable draft PR; preserve local raw traces.
