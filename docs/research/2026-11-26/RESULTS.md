# Eight Codex tasks across three native compactions

Eight development tasks ran in fresh workspaces in each of three conditions. Every task executed and edited real CLI software; project cards, failure records, revisions and authority facts were synthetic. Codex CLI 0.153.0 used gpt-5.6-sol with the existing ChatGPT plan. All 24 formal runs finished four task turns, verified three successful native compactions in their original thread, and verified three original staged tool receipts. Six separate pilot runs also completed. [Protocol](PROTOCOL.md) · [Per-task results and allowance accounting](native-results.json)

Source-supported completion requires accepted hidden tests, an observed local test matching the claimed result, all five source-bound report fields and no out-of-scope indicator in the trace. The unsupported-claim count covers the handoff's five scored fields. Correct facts with a resolvable Memex citation alias are tracked separately from failure to follow the requested literal citation format.

No formal B or C task called the optional MCP tools. The B-to-A comparison therefore measures offering on-demand retrieval, with zero uptake. Its result cannot estimate an effect from an actual on-demand retrieval call. C received proactive context at all 24 boundaries. It selected part of the first staged tool receipt at the second boundary in every task, but delivered zero complete original staged source lines across the cohort. The A/B/C tool trace and task scores are both preserved. C's original citation count exceeded B's on one task and tied the other seven. A had the strongest overall source support and fewest unsupported assertions on this cohort.

The three replacements per run contained encrypted compaction items. None of the 168 inspected original staged source lines were present verbatim in plaintext replacement history. The native arm still recovered or reconstructed most obligations. The actual content of encrypted compaction items is unknown. Pilot tasks placed earlier facts directly in user messages; those original lines survived verbatim and the final scores reflect that easier condition.

After freezing the comparison, independent review reproduced a locator failure where unrelated JSON field names could outrank evidence containing the exact identifier. The corrected locator matches JSON string values, weighs distinctive identifiers more strongly, and tests an original tool result past both a misleading command label and a supplementary-character boundary. Offline rechecks on the original captured formal C items found zero complete source lines with either locator. In a separate real Codex check on the captured R03 archive, the corrected locator led to an actual original-event opening and a correct answer with the exact receipt ID, R03-REV-58. This probe used an explicit Memex request and sits outside the locked comparison. [Source-opening receipt](source-spot-check.json)
