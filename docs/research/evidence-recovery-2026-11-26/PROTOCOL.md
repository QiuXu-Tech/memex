# Evidence recovery with native Codex compaction

The prior native study observed zero voluntary Memex calls in the on-demand arm, incomplete proactive evidence, and three consecutive native compaction boundaries per execution. This experiment compares required actual retrieval with a gate that triggers only when a high-impact claim lacks valid original evidence. The opt-in prototype checks test results, current-version candidate claims, and operation authorization evidence. Archival authorization text is a fact to verify and grants no external permissions.

## Formal native protocol

- Use 24 runnable but synthetic development fixtures in all three conditions. Lock eight as holdout. Use independent threads and workspaces, the shared installed ChatGPT-authenticated Codex model and reasoning level, and paired initial/final prompts followed in a balanced order.
- First execute the software task in a workspace containing a staged synthetic record. Require the actual tool stdout to contain every original receipt line and persist its hash and thread/item identity. Remove the staged file before the first requested compaction and preserve the underlying source outside the model workspace. Reuse the standard Codex app-server, with 3, 6, or 10 explicitly verified native boundaries between the implementation and decision turns.
- A allows native continuation with the common current evidence prompt. B runs the actual Memex search and original-event open RPCs as a forced positive control at the decision boundary. C applies the same Memex runtime and evidence budget but runs only when the gate finds a missing, stale or conflicting current original. Both gate arms log every MCP call, the original opened source or explicit reason for abstention, and the host submission hash. Use a separate Codex context field for the verified excerpt or diagnostic information. The final claim remains the model's actual answer. The version field in the common prompt is the candidate version being verified, so raw value accuracy for that field alone does not prove discovery.
- Use exact o200k_base reference counting on each injected evidence item with a 1,200-token ceiling. Host telemetry separately records cumulative provider input and cache. A missing, truncated or mismatched receipt stays visible in the diagnostics. Preserve actual provider errors and never substitute pilot or offline outcomes for unrun cells.
- Eligibility, existing proof, scope, truth values and required original citations are frozen independently of arm answers. Score actual retrieval attempts, verified original opens, source-backed correctness and final unsupported claims separately. Compare A to B, and B to C, on matched tasks and the reserved holdout. Measurements are scoped to this installed host, controlled tasks and explicit decision boundary.

## 100M archive protocol

Use the independently hash-verified existing 100M synthetic corpus. Lock at least 600 search requests with original candidate and negative controls. Replay the identical query bytes in independent MCP processes on the base and candidate configurations three times each. Record p50, p95, Top 5 hits, negatives and scope probes. Preserve the ordinary search path and use the evidence-search feature only in the targeted study entry. Report diagnostic misses beyond the frozen query set separately.
