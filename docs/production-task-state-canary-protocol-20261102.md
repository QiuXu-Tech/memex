# Post-repair task-state follow-up protocol — 2026-11-02

This separately registered follow-up uses four previously unused public issue owners. The [frozen registration](assets/benchmarks/production-task-state-canary-20261102/registration.json) records issue-specific acceptance criteria, source archive hashes, randomized-order commitment, budgets, code commit and protocol. The [source manifest](assets/benchmarks/production-task-state-canary-20261102/source-manifest.json) and [blind review plan](assets/benchmarks/production-task-state-canary-20261102/review-plan.json) were published before task execution. The first two candidates were selected before two more were added; their [initial manifest](assets/benchmarks/production-task-state-canary-20261102/initial-two-manifest.json) is retained.

The follow-up was designed after the earlier 30-issue cohort revealed invalid search-limit arguments. It evaluates the repaired bridge and is reported separately, rather than as part of the earlier pre-registered effect estimate. Each randomized pair has three independent Claude Code sessions per arm; both arms receive their own handoffs and source access, while one also has Memex. The first two cases run before the remaining two so failures and usage can be checked. A frozen client-list-price reservation limits spending; this is not an invoice. Anonymous packet commitments will be published before AI reviews, and failures remain in the record.

These are compressed historical, read-only public-issue triage exercises, not live production tasks or verified patches. Source snapshots can postdate issue comments, and the models may have encountered public content in training. AI assessment is not human review, and unavailable provider charges remain unknown.
